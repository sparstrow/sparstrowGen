title: Sparstrowgen runs on its own now
---

**New**

- **Sparstrowgen starts its own server.** Until now the app quietly depended on
  one already running on the same computer — which was true on the machine it
  was built on and nowhere else. It now starts and looks after that server
  itself, so the app works on its own.
- **Settings → Server.** Sparstrowgen keeps your work in a Supabase project of
  your own, and this is where you tell it which one. The keys are held in
  Windows' own credential store, never in a file and never inside the installer
  — an installer is a public download, and a key inside one is a key given to
  everybody. Sparstrowgen will refuse to save them rather than write them
  somewhere readable.

**Fixed**

- **Your computer appears after you sign in.** In 0.3.1 this still did not work.
  Two separate reasons: the app checked whether its own service was ready in a
  way that could never succeed, and it asked to be registered against a server
  that was not there. Both are fixed, and the app now waits for both halves to
  be ready before registering.
- **Updating no longer feels like a reinstall.** It applied itself with the full
  installer wizard visible, and left the previous version's background service
  running — which then blocked the new one from starting. Updates now apply
  quietly and shut the old service down first.

**If you are updating from 0.3.1**

Nothing to do. Your computer should appear on the Machines tab within a few
seconds of the app opening, with no button to press.

**Still not working**

- Sending a message to an agent gets no reply. An agent created in the app does
  not yet exist on any computer, so there is nothing for it to run. That is next.
- Signing in for the first time on a *new* computer needs the web app running.
  Updating an already-signed-in computer, like yours, is unaffected.
