title: Signing in works again

**Fixed**

- **Signing in no longer fails with "Could not reach http://localhost:3000".**
  0.3.2 still looked for a web server that this app stopped shipping two
  versions ago, so on a fresh computer sign-in could not start at all. It now
  uses the server the app runs itself, which is already on your machine.
- **The window notices when its service comes up.** It checked once, a moment
  too early, and then went on saying the server was not running for as long as
  the app stayed open.
- **A background service that dies is now noticed.** If Sparstrowgen found a
  service already running when it started, it handed over to it and never looked
  again. When that one later stopped, your computer showed as unreachable until
  you restarted the app. It now checks every fifteen seconds and takes over.
- **Signing in tells you where it has got to.** It says whether it is waiting
  for your browser or connecting this computer, instead of showing one message
  for the whole thing including the slow part after your browser is done.

**Behind the scenes**

- **Two copies of Sparstrowgen can now run on one computer without harming each
  other.** They shared the same two network ports, and because the app adopts a
  service it finds already running, the second copy would quietly start working
  on the first copy's data. Each install now has its own ports. This matters
  because a development build and your own app should never be able to touch
  each other's work.

**Still not working**

- Sending a message to an agent gets no reply. An agent created in the app does
  not yet exist on any computer, so there is nothing for it to run. That is next.
