# Plan: Curator — close the office-hours parity gap

Generated by `/office-hours` on 2026-07-14
Branch: `docs/factory-workflow-v2`
Status: APPROVED
Mode: Intrapreneurship (internal engineering process)

## Problem Statement

The Curator (`docs/workflows/agents/curator.md`, `curator.skill.md`, `.claude/skills/curator/
SKILL.md`) is meant to be Sparstrowgen's version of the `/office-hours` decision-brief craft —
forcing questions, reframe-and-confirm, decision briefs with options/pros-cons/recommendation.
The owner's read: it doesn't feel like office-hours — "very little significance."

## Findings (line-by-line comparison against the live `/office-hours` skill)

**Already inherited correctly** (not a shallow copy): forcing questions, reframe-and-confirm,
the decision-brief shape (options, ✅/❌, Recommendation, "if we pick wrong"), premise-challenge,
one-question-per-turn, escape hatch, and a pushback-pattern table adapted to intake triage.
Verified working in this session's own Curator run (0005 reopen produced a real D1 brief).

**Concrete gaps — specific missing fields, not a wholesale rewrite:**
1. No `Completeness: X/10` scoring (or "differs in kind, not coverage" note) on decision briefs.
2. No `ELI10:`-disciplined plain-English stakes line — has "What's being decided" (similar
   intent) but not held to the explicit "a 16-year-old could follow" bar.
3. No dual-scale effort labels (`human: ~2 days / CC: ~15 min`) on effort-bearing options.
4. Looser pros/cons floor: requires only ≥1 pro + 1 con per option, no length floor — vs.
   office-hours' ≥2 pros + 1 con, **each individual pro and con** ≥40 characters (not just the
   option as a whole).
5. No Voice section (banned-word list, "lead with the point," a concrete good/bad example pair).
6. No tool-resolution / BLOCKED handling if `AskUserQuestion` isn't callable in a given host —
   currently nothing stops Curator from silently faking a decision in prose instead of stopping.

**Likely non-defect contributor to "low significance":** Curator's "proportional effort" design
deliberately gives trivial captures a fast pass with little dialogue. If most captures so far
have been simple, correct light-touch behavior can still read as underwhelming next to
office-hours, which never lightens up. This is a design tradeoff, not a bug.

## Premises (confirmed 2026-07-14)

- P1. The gap is the six items above, not a wholesale rewrite of Curator's dialogue mechanics —
  **agreed**.
- P2. "Proportional effort" stays: Curator stays light-touch on trivial captures, and only runs
  at full office-hours intensity when reclassifying / merging captures / routing toward new
  work — **agreed**.

## Approaches Considered

**A — Minimal patch:** add items 1-4 + Voice section only. S effort, low risk, leaves the
AskUserQuestion-unavailable case unhandled.

**B — Minimal patch + tool-resolution correctness (chosen):** everything in A, plus explicit
Track-A guidance to prefer any `mcp__*__AskUserQuestion` variant and report **BLOCKED** (not a
faked prose decision) if none is callable. S/M effort, low risk.

**C — Full parity + question-tuning memory:** A + B, plus a new preference-memory mechanism
(`tune: never-ask` equivalent) for recurring routing questions. L effort, medium risk — no
existing Track-A state-storage convention to build on; speculative infra for a pattern not yet
observed in real use. Deferred: revisit once the improved Curator has been used enough to see an
actual repeated-question pattern (violates CLAUDE.md's "no speculative future-proofing" bar
otherwise).

## Recommended Approach

**B.** Closes every concrete gap found with a small, safe diff to the same three files, using
the identical "canonical doc + two regenerated skill files" pattern already proven on the
Listener skill's guardrail additions this session.

## Implementation Tasks

1. `docs/workflows/agents/curator.md` — canonical: add the six items to the decision-brief
   format spec, self-check checklist, and a new Voice section (adapt office-hours' banned-word
   list + one good/bad example, scoped to intake-triage language).
2. `docs/workflows/agents/curator.skill.md` — regenerate from the canonical doc (portable,
   in-app agent).
3. `.claude/skills/curator/SKILL.md` — regenerate from the canonical doc (Claude Code entry
   point), including the AskUserQuestion tool-resolution / BLOCKED guidance (Track A only — the
   in-app Track B agent has its own UI-confirm mechanism (the P10 Manager draft pattern: emit,
   surface in the UI, user confirms) and doesn't call the `AskUserQuestion` tool at all, so it
   has no equivalent "silently fake it" failure mode to guard against).
4. Regeneration is manual (same as the Listener update this session): whoever edits the
   canonical doc copies the relevant sections into both derived files by hand and verifies all
   three agree before committing — there's no automated generation script yet.
5. One commit, pushed — same discipline as the Listener guardrail commits.

## Success Criteria

- All three Curator files agree (no drift) and each decision brief the Curator produces going
  forward includes: Completeness/kind-note, ELI10 line, effort dual-scale (when relevant),
  ≥2 pros + 1 con per option at ≥40 chars, and reports BLOCKED rather than faking a decision if
  AskUserQuestion isn't callable.
- Proportional effort is unchanged — trivial captures still get a fast pass.
