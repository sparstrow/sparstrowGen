# docs/specs — approved designs

One file per topic, named `YYYY-MM-DD-<topic>-design.md`.

Written by the superpowers `brainstorming` skill and committed **before** planning starts. A spec is
the design the owner approved: purpose, constraints, success criteria, the approaches considered and
why this one, architecture, components, data flow, error handling, testing. No placeholders, no
"TBD".

This path overrides the skill's `docs/superpowers/specs/` default — see `CLAUDE.md`, Part II.

A spec may take an optional review pass (`/plan-ceo-review`, `/plan-eng-review`,
`/plan-devex-review`, `/autoplan`) before it becomes a plan in [`../plans/`](../plans/).

Architecture specs that predate this flow live in [`../planned/`](../planned/) and stay there.
