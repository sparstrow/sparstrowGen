## Attack surface

69 HTTP handlers (67 behind bearer token; 2 public: static UI + SPA fallback), 2 WS channels (event
stream + terminal pty, both authed), 2 CI workflows, 3 background jobs (cron/indexer/watcher).

Spawn paths (`node-pty`, `child_process`) all use **arg arrays with `shell:false`** — no shell
concatenation. SQL is fully parameterized (drizzle + `?,?` placeholders), FTS input escaped. Electron
locked down (`contextIsolation:true`, `nodeIntegration:false`, minimal preload). No UI HTML-injection
sinks (React). No git-history secrets, no tracked `.env`.

**#1 drizzle-orm SQLi** — direct dep below the 0.45.2 fix. The CVE bites only when *user input is used as
a SQL identifier* (table/column name). Every query was traced: all identifiers are static schema refs,
all values are bound — **no in-app exploit path today**. Bumped anyway to guard future code.

**#2 tar path traversal** — fastembed pulls tar 6.2.1 to extract the embedding model on first run. A
malicious/MITM'd model tarball with hardlink/symlink traversal entries could write outside the cache
dir. Gated on model-host integrity (HTTPS). **Not fixed in this pass** — see Remediation below.

**#3 @fastify/static** — serves the built UI, registered *outside* the auth scope (static GETs are
unauthenticated). Directory listing is off (neutralizes one advisory); the encoded-separator route-guard
bypass remains. Mitigated by `127.0.0.1` + `CORS origin:false`. Bumped to ≥9.1.1.

**#4 pnpm/action-setup@v4** — third-party action on a mutable tag. Both workflows trigger on
`pull_request` (not `pull_request_target`), use no secrets, and the author-check SHA interpolation is
safe. Limited blast radius. Pinned to a commit SHA + added `permissions: contents: read`.

## Known persistent (below daily gate, carried forward)

- **gemini cmd.exe arg injection** (`packages/core/src/providers/gemini-cli.ts:58`) — still spawns via
  `cmd.exe /d /s /c`. Now **only reachable by an authenticated operator** who can already run agents with
  `bypassPermissions`+Bash (RCE by design). No untrusted-input path reaches the args. Defense-in-depth only.
- **vault RAG prompt injection** — memory notes inject into agent prompts; requires the user to import an
  untrusted `.md`. No remote writer. Mitigate by framing injected memory as untrusted reference and
  keeping agents least-privilege.

## Hardening notes

- `toAbsPath` prefix check still lacks a trailing separator (`memory/vault.ts:34`) — not reachable
  (slugify neutralizes `../`), fix anyway.
- No `setWindowOpenHandler` / `will-navigate` guard in Electron main (`desktop/src/main.ts`).
- js-yaml DoS via gray-matter — excluded as DoS, cleared opportunistically with the other bumps.
- Token injected into served UI HTML (`server.ts:111`) — deliberate same-origin design, acceptable for a
  single-user localhost app.

## Remediation applied (2026-06-28)

**Fixed:**
- `drizzle-orm ^0.44.2 → ^0.45.2` (resolved 0.45.2)
- `@fastify/static ^8.3.0 → ^9.1.1` (resolved 9.1.3)
- `pnpm-workspace.yaml` override `js-yaml@<4.1.2 → >=4.1.2` (resolved 4.2.0)
- CI: `pnpm/action-setup` pinned to SHA `fc06bc1257f339d1d5d8b3a19a8cae5388b55320` (v4.4.0);
  `permissions: contents: read` added to `ci.yml` and `author-check.yml`

Verified: `pnpm typecheck` ✅ (6/6 packages), `pnpm test` ✅ (25/25),
`pnpm audit --prod` **11 → 7 vulnerabilities**.

**Deferred — Finding #2 (tar):** Forcing `tar >=7.5.11` is a 6→7 major bump under fastembed, which calls
`tar.x` via an esModuleInterop default import (`tar_1.default.x`) and pins `tar@^6.2.0` even in its latest
2.1.0. tar 7's hybrid ESM/CJS shape can make `tar_1.default` undefined, silently breaking model
extraction (typecheck won't catch it). Needs a runtime model-download test before overriding. The 7
remaining `pnpm audit` advisories are all this tar/fastembed chain.
