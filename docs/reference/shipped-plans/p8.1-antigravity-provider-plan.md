## PROBE RESULTS (2026-07-08, agy v1.1.0, log-confirmed)

Probed `agy` directly and read `~/.gemini/antigravity-cli/cli.log` (the authoritative
source). Findings that MOVE the plan:

- **R2 RESOLVED — stdin works.** `agy --print` reads the prompt from stdin
  (`printmode.go:89 promptLength=83`). No temp-file fallback needed for transport.
- **R1 RESOLVED — tokens are the display names.** `--model "Gemini 3.5 Flash (Low)"` →
  `model_config_manager.go:157 Propagating selected model override to backend:
  label="Gemini 3.5 Flash (Low)"`. `settings.json` also stores the model as the display
  name (`"model": "Gemini 3.1 Pro (High)"`). So `KNOWN_MODELS["antigravity"]` = the exact
  `agy models` display strings.
- **NEW CRITICAL — model selection needs prompt-as-ARG.** `--model` only takes effect as
  `agy --model "X" --print "<prompt>"` (prompt as the arg). With a **stdin** prompt (the
  gemini pattern: `printf … | agy --print --model "X"`), `--print` greedily swallows
  `--model X` into the prompt TEXT and the run silently uses the `settings.json` default
  model. Proven: stdin probe echoed `--model` back in the response and logged NO model
  override. **Consequence: the "mirror gemini exactly" approach (stdin + `--model`) makes
  per-agent model selection a SILENT NO-OP.** This invalidates the naive item-4 spawn.
- **The tension:** prompt-as-arg makes `--model` work but re-arms the Windows ~32KB
  `CreateProcess` argv ceiling; `finalPrompt` (preamble + directives + ≤8KB memory + task)
  can exceed it. Transport approach is now a real decision — see "TRANSPORT DECISION".

## TRANSPORT DECISION — RESOLVED (owner, 2026-07-08): `--print -`

Owner found the clean solution: pass the literal `-` as `--print`'s argument
(`agy --model "<display>" --print -`). The `-` is the explicit stdin marker, so
`--print` no longer swallows the trailing flag AND the prompt still arrives on stdin.
**Log-verified:** `agy --model "Claude Opus 4.6 (Thinking)" --print -` with a stdin
prompt → `Propagating selected model override: label="Claude Opus 4.6 (Thinking)"`.
This beats all three options below — robust for any prompt size (no argv ceiling) AND
guaranteed per-agent model. Implemented: `--model <m> …perm …add-dir <dirs> …extraArgs
--print -`, `viaCmdShell:false`, prompt via `stdinData`. **STATUS: BUILT — typecheck
6/6, 323 core tests (11 new), UI build green.**

Superseded options (kept for the record) for `buildHeadlessSpawn`:
- **A. prompt-as-arg + length guard (recommended).** `agy --model "<display>" --print
  "<finalPrompt>"`, `viaCmdShell:false`. If the assembled command line would exceed a
  safe ceiling (~30KB), fall back to stdin transport and accept the settings.json default
  model for that oversized run (logged). Per-agent model works for the common case
  (memory cap is 8KB, so typical prompts are well under 32KB); only pathologically large
  task prompts degrade. No global state, concurrency-safe.
- **B. stdin + per-run settings.json via HOME override.** Robust for any prompt size and
  selects the model, but relocating `HOME`/`USERPROFILE` per spawn risks breaking agy's
  auth/state (both live in `~/.gemini/antigravity-cli/`). More code, needs an auth-share
  probe. Deferred unless A's degradation is unacceptable.
- **C. stdin + single global model (settings.json).** Simplest, robust, but NO per-agent
  model — defeats "agents use the models of antigravity" (plural). Rejected as the default.

## What Antigravity actually is (probed, not assumed)

`agy --version` → `1.1.0`. `agy models` →
`Gemini 3.5 Flash (Low/Medium/High)`, `Gemini 3.1 Pro (Low/High)`,
`Claude Sonnet 4.6 (Thinking)`, `Claude Opus 4.6 (Thinking)`, `GPT-OSS 120B (Medium)`.

Relevant flags (`agy --help`):
- `--print` / `-p` / `--prompt <text>` — run ONE prompt non-interactively, print the
  response. **Plain text only — there is no `--output-format json`** (gemini had one).
- `--model <token>` — model for the session.
- `--add-dir <dir>` — add a workspace directory (repeatable).
- `--dangerously-skip-permissions` — auto-approve tool permissions (yolo).
- `--mode accept-edits|plan` — execution mode.
- `--conversation <ID>` / `--continue` (`-c`) — resume a prior conversation.
- `--project <ID>` / `--new-project` — project scoping.
- `--sandbox`, `--print-timeout` (default 5m).
- `agy.exe` is a **real binary**, not an npm `.cmd` shim.

## Premises (to confirm at the gate)

1. Integrate Antigravity as a **CliProvider** (spawn `agy --print`, stream stdout),
   mirroring `gemini-cli.ts` — NOT a direct-API provider. It's a CLI binary; the user
   installed the CLI.
2. This change is **additive**. Add the `antigravity` provider; do **not** rip out the
   38 existing `gemini-cli` references in the same PR. Gemini is already UI-disabled
   ("Gemini CLI (retired)"); full backend removal is a separate cleanup.
3. Scope = **foundational parity** with gemini-cli: headless run + health check + model
   list + system-prompt-in-band + no MCP (agents use the sparstrow-memory CLI and fenced
   ```` ```sparstrow ```` directives). Out of scope for now: conversation resume
   (`--conversation`), cost/token stats (agy `--print` reports none), streaming events.

## Risks / open technical questions

- **R1 — model token mapping.** `agy models` prints display names with spaces/parens
  (`"Gemini 3.5 Flash (Medium)"`). The `--model` flag likely wants a canonical token,
  not the display string. Probe during impl: `agy --model "<candidate>" -p "ping"`.
  `KNOWN_MODELS["antigravity"]` must hold whatever `--model` accepts.
- **R2 — long-prompt transport (HARD GATE, F2).** The executor writes `stdinData` to the
  child's stdin for any provider (`run-manager.ts:476`, stdio piped), so transport is not
  the issue. The unknown is agy's behavior: does `agy --print` read the prompt from stdin
  when given no arg value? `finalPrompt` = preamble + directives + `<memory>` + task
  (`run-manager.ts:315`) routinely exceeds the Windows ~32KB `CreateProcess` command-line
  ceiling, so arg-passing would silently truncate/fail on real runs. **Probe this before
  writing the provider.** If agy does NOT read stdin, the temp-prompt-file fallback is
  mandatory, not optional.
- **R3 — no structured output.** Plain-text `--print` means no cost, no token stats, no
  machine error field. `extractResult` error detection is empty-stdout only; nonzero-exit
  failures are caught by `finalize` on the run path but NOT on the `completeOnce` draft
  path (F1). Acceptable at parity; revisit if agy adds a JSON mode.
- **R4 — pre-existing orphaned branch (corrected).** `providers.ts:32 secretKeyForProvider`
  has `case "gemini-api"` returning `SECRET_GEMINI_API_KEY`. It's orphaned (no `gemini-api`
  provider registered), not type-dead — the fn takes `id: string`, so route params could
  still reach it. Out of scope to fix here; do not mischaracterize as dead.
