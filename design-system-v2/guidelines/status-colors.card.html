Each token is a tinted surface; its -foreground pair is the text that sits on it. That is the shape to copy — bg-warning with text-warning-foreground, opacity modifiers welcome (bg-warning/5, border-warning/30). Both modes are already defined, so a dark: variant on a status colour is a sign someone hand-rolled a palette value instead.

Approval is a fifth status, not a shade of warning. Blocked and awaiting approval are triaged differently and must be separable across a room. Hue 310 keeps it clear of info (255) and of the Violet brand preset (285).
Named rule — Identity Is Not Status. No actor-identity hue sits within 20° of a status hue. The palette shipping today breaks this: actor-avatar.tsx hashes names onto emerald, amber, and rose — which are success, warning, and danger — so an avatar can currently read as a state it has nothing to do with. Identity is also never themed: if a user accent could recolour it, two agents could collapse to one hue and the palette would stop doing its only job.
Neither has been contrast-measured. DESIGN.md §2 requires measurement before a colour ships, and the model used to check it could not reproduce §2.3’s own published figures — see doc/KnownGaps.md G-21. Specified by hue and constraint is where these honestly stand.
