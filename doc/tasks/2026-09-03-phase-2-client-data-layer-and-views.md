it end to end.

## Four defects found by running it

None of these were visible to `tsc`.

1. **`"darwin".includes("win")` is `true`.** Every Mac rendered a Windows logo.
   Now matches `process.platform` exactly before any substring test, and
   `platform-mark.test.ts` opens with that case.
2. **The status was announced twice per row** — the tile's `sr-only` label plus
   the visible text.
3. **Tailwind was not scanning `packages/views`.** Measured, not guessed: with
   the `@source` line removed, the status dot computes to `width: 0px`. The
   trap is narrower and nastier than "shared component loses its styles" —
   utilities the app uses elsewhere keep working, so only classes unique to the
   package break, above all **arbitrary values** like `size-[9px]` which cannot
   be generated by coincidence. The component looks 90% right and prints no
   error.
4. **`@sparstrow/shared` used `Buffer`** — a Node global — in a schema validated
   on both sides, so any browser importing it got a package that could not
   typecheck without `@types/node`. Now `TextEncoder`.

## One structural fix the source-export model forced

`packages/ui`'s 32 files imported each other through a `@/` alias defined only
in its own `tsconfig.json`. `apps/web` papered over that with a matching `paths`
entry; `packages/views` could not, because **a package that exports source must
compile inside its consumer's config**. Rewritten to relative imports, and the
subpath `exports` now resolve extensionless.

`apps/desktop` would have hit this identically in Phase 3. It is the kind of
defect that only appears when a second consumer exists — which is the argument
for building the second consumer early rather than last.

## Deliberately not done

- **No WebSocket yet.** `runs/queries.ts` documents why `useRunEvents` is not
  polled: run events are pushed, and a poll would both duplicate the WS and
  make a finished run ask forever. The server-owned WS lands with the slice
  that needs it.
- **No mutations in `packages/views`.** `apps/web`'s `/machines` screen drives
  rename/revoke/remove through Server Actions; pulling those in would have
  dragged Phase 5 forward and made the component un-renderable outside Next.
  `MachineList` is read-only.
- **`apps/web`'s existing screens still use `@web/api/hooks`.** Both layers share
  one `QueryClient`, so there is one cache, not two views of one row.

## New in the registers

Nothing. The four defects above were fixed in the same change that found them,
which is the outcome `KnownGaps.md` exists to make unnecessary.
